WHAT LIMITED IT  Not host-device transfer (8 bytes in, 8 bytes out per point). VRAM did
  bind at the top: batch 262,144 took card use to 11.4 GB, the largest that fitted beside
  the other servers, so the curve was cut off, not flattened. The real limit is that the
  scorer is SEQUENTIAL where it counts - node placement and label placement each read an
  occupancy set the previous node just wrote, so they stay a per-node loop: 120 window x
  hop groups x ~17 nodes x up to 28 probes = tens of thousands of tiny kernel launches per
  batch. Windows hold only 5-17 nodes and 4-18 links: almost no width to feed 8,960 cores.
  The crossing term - the one piece that vectorises cleanly, <=153 fixed pairs per window -
  is NOT the bottleneck. A PROPER PORT: one hand-written CUDA kernel, one thread per
  (point, window), occupancy as a small open-addressed table in shared memory, all 40
  windows inside the kernel, int32 throughout. Tens of millions is plausible that way;
  array-at-a-time CuPy - what was actually claimed - got a third of the way.
